# BeanPod「朋友圈」功能分支执行计划

交给负责实现的 agent。交付物是 Mac 端一个可使用的一级模块。从导入一段新对话，到认出老朋友、整理往来、点回原话，整条路径都要在真实 App 里走通。

## 1. 最终用户体验

1. 在侧栏点「朋友圈」。首页按最近交流时间倒序列出已确认的人和待认识的人。每行有固定颜色的圆头像、名字、最近交流时间和一句话题。已确认显示姓或名字首字；未知显示 A、B、C……。支持按姓名或备注搜索。
2. 第一次遇到新声音，清晰且能归为同一人的发言组成「陌生人 A」。同一人的多句话只形成一张卡。下一条录音再次可靠匹配时沿用该卡。编号跨天、改名、重启保持稳定，Z 后用 AA、AB，已分配的编号不回收。
3. 打开卡片，先试听几段代表发言。可以填姓名、关联已有联系人、从磁盘多选音频，或从已有录音截取一段作样本。也可以先创建具名联系人，再附样本，等下次遇见。档案颜色和身份随改名保留。
4. 人物页显示简要信息、最近聊的事、共同往来和按日期排列的对话。每条自动生成的信息带录音和时间，点一次能回听。支持修改或移除。没有可核实的信息时留空。
5. 发现同人两卡，系统提示候选。用户试听确认一次，系统自动合并历次对话、样本与往来，去除重复引用，并允许撤销。发现某一句归错人，从原句改归属即可，其他人的发言保持原归属。
6. 第一次启用时可以添加「我的声音」。本人作为对话参与者参与识别，不占联系人名额。身份未设置时，可以手动标记「我」或确认「这是我参与的对话」，无需为使用通讯录先录一段自己的声音。

## 2. 开工位置、基线和范围

计划编制时，本地与远端 main 都是 0e883bbe9daff0c1f13ea6ad4e3165ea2b2fc734。功能分支为 feat/friends-circle。当前工作区已建分支，接手先检查：

```sh
git status --short --branch
git branch --show-current
git log -3 --oneline
git worktree list
```

看到 feat/friends-circle 后继续。在同一台机器的其他 checkout 执行时，先通过 worktree list 找到持有该分支的工作区。遇到用户的未提交改动，保留并避开冲突文件。不要通过 reset、clean 或覆盖文件重建起点。若换了基线，重新核对下表中的符号和存储后再落代码。

## 3. 实施顺序与逐阶段验收

### P0　先跑基线、准备独立测试库

**已实测的开工问题（2026-11-26）**：在基线的两份干净临时副本上验证。XcodeGen 生成成功，`swift test` 通过全部 22 项。原版 Mac 目标在 Xcode 27.2 下编译失败，错误位于 `App/NotchShow.swift:256`，内容为 `conformance of 'TornBottom' to protocol 'Shape' crosses into main actor-isolated code`。第二份副本仅应用现有提交 `ab8b06f` 中的单行修复（`TornBottom` 声明加 `nonisolated`），同一 Mac 构建通过。该验证采用临时副本，功能分支只含计划。接手时先检查 `git show --stat ab8b06f`，若复现同一问题且本分支仍缺这一行，可单独执行 `git cherry-pick ab8b06f`，再跑构建；基线已修好时跳过。

- 记录提交、系统、芯片、内存、Xcode 版本、可用空间。先按第 7 节构建与测试，记下已有错误。历史库兼容测试使用去标识样例，UI 用独立测试库。先确认实际目录，再启动或写入。已有 Demo 库可能是用户资料，生成演示脚本会写入固定目录；有现存内容时用可配置的临时测试根目录。
- 准备经过参与者同意的测试音频并在库外保存人工答案。至少涵盖「我」和两位重复出现的联系人、另一位从未登记的人、单人、双人、多方、抢话、噪声、远近变化及跨天重逢。另备无原音的旧文字稿、播客、损坏音频、超过一小时的长输入。长输入可用获准的测试素材拼接来测资源消耗；跨天识别必须用独立录制的样本。
- 分开登记音频、调参音频和最终验证音频，同一段录音的切片不能跨集合。录音日期、说话人代号、起止时间、是否重叠由人工标注。私人原音、姓名、向量和业务文字稿留在本地测试目录，仓库只保留可公开的夹具或生成方法。
- **退出条件**：能复现原版结果，确认测试库路径，列明哪些声学场景有样本。暂缺跨天或多人样本时可继续 UI 和数据工作，真实识别验收标待验证。

### P1　先用独立录音跑通本机识别

- 建一个最小实验：输入音频及已确认参考样本，输出每个发言区间的起止毫秒、录音内临时说话人、重叠标记、候选人物及匹配分数。处理顺序为检测人声、划分发言与说话人、从单人清晰部分取向量、和已登记样本比对。文字内容、人名关键词和音量不能代替声纹。
- 初选本机可运行的 [pyannote Community-1](https://huggingface.co/pyannote/speaker-diarization-community-1) 做录音内分人，[SpeechBrain ECAPA](https://huggingface.co/speechbrain/spkrec-ecapa-voxceleb) 提取可跨录音比对的声纹。允许换用已验证能完成同一任务的本机实现。先用当前 Mac 验证安装、模型访问条件、CPU/可用加速方式、内存和离线运行，再确定打包方式。实验使用隔离环境；模型及依赖固定版本，记录来源、许可、校验值和可重复安装步骤。需用户接受模型条款时明确提示。
- 单独校准「自动认作某人」「建议人工比对」「证据不足」三个区间。按照第一、第二候选差距处理相似声音；无参考人物时应能形成陌生人。重叠、过短、听不清的片段保留待确认，不能每段都创建新人。陌生人跨录音匹配用清晰代表片段，未经人工命名的聚类始终可拆；自动匹配结果不得自动进入已确认声音样本集。
- 采集每小时耗时、峰值内存、误认与漏认。模型不可用时页面可继续维护人物和回听；显示具体原因、安装或重试入口。跨天识别实验未过时，允许开发建议匹配，自动署名保持关闭。
- **退出条件**：同一条真实录音分出两人，另一日录音能比较已登记的人，新人有拒识路径；保存去标识实验结果、模型版本及失败案例。用假模型验证界面时明确标为开发样例。

### P2　建立独立人物库和身份规则

P1 交给 App 的接口要能脱离 SwiftUI 做测试。输入传本机文件 URL、音频指纹、任务 ID 和模型版本，取消按任务 ID。每段至少返回 `startMs`、`endMs`、`localSpeakerID`、`overlap`，候选项带 `personID` 和分数；模型失败返回明确的失败状态。区间统一从原始音频零点起算、左闭右开。拒绝负时间、倒置区间、越过音频末尾的区间和模型版本不兼容的向量。若采用本机子进程，用参数数组传文件路径；依赖环境和模型状态在 App 内可检查。发布前用一份全新测试环境从 App 的安装入口跑一次，再断网复测。

建议在录音库旁设置按正式库／Demo／测试库隔离的 Friends 数据目录。人物和发言关联采用支持事务的本地 SQLite，原音继续引用现有 WAV。执行时如果基线已具备同等本地存储和事务能力，复用已有层。给关系库加版本和迁移测试。以下是最小数据契约，字段命名可随代码规范调整。

| 对象 | 必需数据及约束 |
|---|---|
| 人物 | 稳定 UUID、显示名、陌生人序号、头像颜色、身份状态、是否为本人、人工备注。姓名可重复，序号唯一；改名沿用 UUID。 |
| 声音样本 | 样本 ID、所属人物、来源文件或录音及起止毫秒、人工确认状态、特征模型版本、本地特征、去重用的内容指纹。外部文件复制到受管目录，用户原文件留在原处。删除样本后重算人物参考特征。 |
| 发言与归属 | 原音身份（录音 ID 加音频指纹）、区间、临时说话人、人物 ID 或空、自动／人工来源、分数、分析版本。以原音区间定位，ASR 句子下标仅用来展示。 |
| 对话与人物资料 | 对话关联本人的参与状态；话题、往来事项、简要资料均关联人物、录音、原文证据区间、参与者及人工编辑状态。一次多人对话可关联多人，同一人名下只计一次。 |
| 作业及纠错 | 记录输入指纹、模型和规则版本、进度、失败原因；持久化人工纠错、拒绝配对和可撤销的合并记录。防止重新分析反复推荐已驳回的同一配对。 |

人物库负责跨录音身份；旧 Segment.speaker 继续表示录音内标签。读取老库时保留既有手工标记，并允许用户主动关联人物。新匹配通过统一的显示名查询呈现在文字稿；旧 CLI、导出等读取路径若需要投影到录音内标签，用确定性映射并测试。多存储写入若中断，应能从权威数据重建派生结果，避免半合并或录音内标签错位。损坏或高版本库报告可恢复错误，禁止静默初始化覆盖。

**退出条件**：旧库可打开；同名两人可共存；改名、样本增删、陌生人编号在重启后正确；同一任务重复提交和中途退出不会产生重复人物或残留半条样本。

### P3　接入真实流水线与来源筛选

1. 新音频可读后触发独立人物分析作业，文字稿可用后再对齐和生成摘要。补上已有文字稿导入、重新转写、转写失败后重试三个入口。首次启用默认处理后续符合条件的录音；历史录音由用户选择范围，显示条数和进度。
2. 默认候选为本人日常对话或明确纳入的会议。录音豆和麦克风也能录到外放；有本人可靠声音或人工确认参与才纳入正式往来。来源不明的导入、飞书会议先核参与；播客、视频、学习素材、语音输入默认排除。允许单条纳入或排除。纯文字只支持已有证据的手工关联，并显示「无原音」。
3. 对齐以声学区间为准，计算与 ASR 句子的时间交集。单一说话人清楚时显示名字；一句包含多人则展示分段或标「多人／待确认」。整篇只有 start=0 时，保留声学时间线可回听，文字稿标明无法逐句归人；未对齐的文字不得归到个人档案。
4. 后台分窗读取长音频，重叠窗口的同一发言在边界去重；窗口内临时编号必须重新比对才能跨窗连接。串行或限并发调度，观察与转写模型同时驻留的内存。支持取消、休眠后恢复、失败手动重试；取消时清理临时文件。持久化结果前再检查原音指纹及录音是否仍在库。
5. 重转写时，同一原音保留人工区间与人物，重新对齐文字；原音被替换时旧的人工绑定进入复核。移入回收站即从人物时间线和摘要中隐藏，恢复后按同一原音复原，永久删除时清理由此产生的引用、片段与特征；独立导入的样本按其自身来源处理。撤销权限或删除人物声音样本后，下一轮匹配必须使用更新后的参考库。

**退出条件**：一条新对话从导入自动出现在人物页；同一录音重跑两次结果不重复；重转写、移入回收站与恢复都实测；无模型、无音频和识别失败时原有转写整理仍可使用。

### P4　完成通讯录、详情、确认与纠错

- **首页**：侧栏一级项「朋友圈」，默认按最近交流排序。在空库展示「添加联系人」「选择录音识别人」。有数据时展示已确认／待认识、搜索和待确认提示。颜色由已保存身份决定，不能每次启动随机生成。中文和英文操作入口都可访问。
- **详情**：头像、姓名、编辑、声音样本、简要信息、最近话题、往来事项、对话时间线。卡片进入后能试听样本，能跳转到指定录音、打开文字稿、定位并播放原句。为无原音、没有对话的新联系人、删除或移动过的录音分别提供明确状态。
- **导入样本**：多选常见音频，如 WAV、M4A、MP3；实际可解码格式在选择器中声明。展示文件名、试听和裁剪范围。多人录音要求用户选清晰的单人区间；单个坏文件不阻碍其他文件，逐项反馈。完成后拔掉外置盘或移动源文件仍能试听。样本入口不得把文件误导入普通录音库。
- **纠正一段**：原句菜单有「这是另一人」「待确认」「标为我」。可选一条或勾选同批多条，预览影响范围。人工归属优先于再分析。人物页、时间线、双方摘要和待办归属随之更新。单句纠正不能把整张卡改名。
- **合并两人**：提供系统推荐和手动选择两种入口。并排试听、显示样本数、对话数与冲突资料，选择保留的姓名后确认。单事务合并人物关联；同一来源区间去重，相似文字不作为去重依据。优先保留人工编辑，冲突内容交给用户选。撤销依据此次变更记录恢复，不回滚整个库；合并后新产生且无法归回原主的内容留待确认。提供移走误分片段的入口。操作中断后应呈现完整的前态或后态。

**退出条件**：从陌生人命名、关联既有人物、单句改人、两卡合并、关闭重开后撤销、从人物页回听，全部可用鼠标在 Mac App 完成。

### P5　从谈话生成有依据的人物信息

1. 使用已纳入的对话、已确认或可靠匹配的发言、临近上下文及说话人身份。人物简要信息仅摘取有明确原文依据的称呼、职责或关系。区分对方自述、别人转述和碰巧提到的第三人。缺证据时留空。
2. 最近话题按实际对话时间排序，重跑时间不能改变顺序。交易及交际按具体事项呈现，标明谁提出、谁承诺、日期与状态。区分报价与成交、预计付款与已经付款、邀请与已赴约；保留否定和条件。多人会议里，提到某人或某笔款不自动记为他的事项。
3. 优先复用本机分析能力。每条自动结果返回来源录音及原句区间，由程序校验来源存在、区间有效、原文能定位，再保存。没有本机整理能力时先显示可回听的最近原句并标明「原话」，摘要可显示待生成。默认不因朋友圈功能把原音、声纹或带姓名的新档案送入已有云端分析路径。
4. 人工修改和移除要持久化；生成结果保留来源与版本。纠错、合并、拆分、原文修改及源录音删除时，只更新受影响的人物和证据。来源失效的自动事项不可继续当事实展示。

**退出条件**：用包含“下周付”“还没付”“第三人已经付过”的多人录音，逐条核对归属、状态和回听位置；修改人工备注后重新分析，人工内容仍在。

## 4. 自动署名与全天处理的放行条件

下面是首版建议门槛，属于开发验收目标。实际数据按下列分母报告，不引用公共模型榜单作为项目实测结果。

| 要检验的事 | 如何测、如何决定 |
|---|---|
| 名字是否标对 | 在未参与调参的跨天录音上，统计正确自动署名数／全部自动署名数，并列出误认次数。首轮至少核对 50 个可独立判断的单人发言、覆盖两天；试用放行建议这批误署名为 0，同时报告样本量。样本不足或发生误署名时先用建议模式。 |
| 系统是否有用 | 已登记人物的正确自动署名数／这些人可辨的全部发言数，建议首轮 ≥70%。另列陌生发言被错标成已知人的次数／陌生发言总数，测试集中应为 0。单独报告重叠、短句和噪声的待确认数，避免全给待确认也被算成通过。 |
| 陌生人是否稳定 | 核对同一陌生人跨录音复现、不同陌生人隔离、误分后可拆。提供按真实人物汇总的卡片数和每次错合并记录。 |
| 可否日常跑全天 | 用目标 Mac 跑一段长录音和一批接近日常总时长的素材。记录总音频时长、墙钟耗时、实时系数（处理耗时／音频时长）、峰值内存、额外磁盘占用、休眠恢复和界面响应。试用目标为在下一批日常录音到来前处理完毕。仅做过短样本实验时，全天处理标待验证。 |

识别效果未过门槛可以交付手动维护和建议识别供试用，交付表里须列明自动署名或全天处理仍待验收。阈值由调参集确定，记录模型版本、第一候选门槛和候选间距后，再跑最终集；修改规则后换独立样本复测。

## 6. 提交节奏和故障处理

每个阶段做一个便于审查和撤回的提交。先提交可重复的模型实验和结果，再提交数据层、流水线、界面与纠错、摘要，最后提交验收所需的测试与使用说明。测试应随对应功能一起添加。每次提交附一句实际验证结果。演示数据、真实人物声纹、模型大文件、密钥、临时构建目录和调试音频不入 Git。

模型下载失败时保留手工模式并说明缺哪一个文件；无真实标注时不调低门槛；基线故障单列；如同一问题连续三次无新证据，停止该项，报告命令、错误、已排除项和缺少的条件。其余独立阶段可以继续。用户授权范围内在本地功能分支工作；推送、创建公开成果和合入主线依当次授权执行。
